# Paralbook

Чтение английских текстов: подборка, библиотека, генерация в чате, карточка слова по второму клику, словарь и тренировка.

## Стек

Next.js 15, React 19, Kysely, PostgreSQL и отдельный Python-сервис обработки текста (FastAPI). База — Supabase через session pooler. Вход свой: пароль в `scrypt`, сессия в httpOnly-cookie. Supabase Auth не используется.

## Запуск

```bash
npm install
```

Скопируйте `.env.example` в `.env` и подставьте свои значения.

Сначала поднимите Python-сервис:

```bash
cd text-service
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python run.py
```

На Windows запускайте именно `run.py`: он включает `SelectorEventLoop`, нужный `psycopg`.

Затем Next.js:

```bash
npm run dev
```

Приложение откроется на http://localhost:5173, сервис — на http://127.0.0.1:8000.

Сборка: `npm run build`, затем `npm start`.

## Переменные

`DATABASE_CONNECTION_STRING` — строка session pooler (`*.pooler.supabase.com:5432`). Прямой хост `db.*.supabase.co` с Vercel не открывается.

`JWT_SECRET_KEY` — длинная случайная строка для подписи сессии Next.

`TEXT_SERVICE_URL` — внутренний адрес Python-сервиса.

`NEXT_PUBLIC_TEXT_SERVICE_URL` — адрес сервиса для прямых загрузок из браузера.

`TEXT_SERVICE_TOKEN` — общий секрет для вызовов Next → сервис.

`TEXT_SERVICE_JWT_SECRET` — секрет для короткоживущих токенов пользователя (загрузка файлов и настройки LLM).

`LLM_SETTINGS_SECRET`, `LLM_LEGACY_SECRET`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_CHAT_MODEL` читает Python-сервис. `LLM_SETTINGS_SECRET` есть только у сервиса; `LLM_LEGACY_SECRET` нужен один раз для перешифровки старых ключей `v1`.

Секреты остаются только на сервере. В клиентский бандл попадает только публичный адрес `NEXT_PUBLIC_TEXT_SERVICE_URL`.

## Нейросеть и text-service

Генерация текста, перевод загруженных книг и работа с LLM-ключами вынесены в Python-сервис.

Пользователь указывает OpenAI-совместимый Base URL, модель и API-ключ. Ключ шифруется AES-256-GCM в `llm_settings`; секрет `LLM_SETTINGS_SECRET` известен только сервису. Ввод и проверка ключа идут напрямую в Python по короткоживущему токену от Next, поэтому Next не хранит и не расшифровывает ключ.

Таблица `llm_settings` должна существовать (тип `user_id` совпадает с `profiles.id`; ниже предполагается `uuid`):

```sql
create table if not exists llm_settings (
  user_id uuid primary key references profiles(id) on delete cascade,
  base_url text not null,
  model text not null,
  api_key_ciphertext text,
  updated_at timestamptz not null default now()
);
```

Сервис сам создаёт `text_jobs` для асинхронных заданий генерации и импорта. Для скрытия ещё не обработанных текстов нужна колонка:

```sql
alter table texts add column if not exists ready boolean not null default true;
```

Старые ключи формата `v1`, зашифрованные Next, автоматически перешифровываются при чтении, если задан `LLM_LEGACY_SECRET`.

Если у пользователя нет личного ключа, используется `LLM_API_KEY` из окружения сервиса. Для локальных моделей (Ollama, LM Studio) ключ не обязателен.

## Добавление текста и загрузка файлов

Текст можно добавить двумя способами.

**Страница «Добавить текст»** (`/text`, кнопка «Добавить текст» в чате):

- два поля — английский и русский текст;
- заполнено только одно поле — сервис переводит его на второй язык (EN → RU или RU → EN);
- заполнены оба — перевода нет, сервис только выравнивает готовые тексты по абзацам и предложениям;
- лимит — 200 000 символов на каждое поле; при превышении задача не создаётся;
- абзацы лучше разделять пустой строкой: при одинаковом количестве абзацев соответствие точнее.

**Страница «Загрузка»** (`/upload`) принимает файл. Поддерживаются:

- `TXT` — с определением кодировки (UTF-8, UTF-16, а также однобайтовые вроде windows-1251; koi8-r — если кодировка объявлена в файле);
- `Markdown` — разметка убирается, остаётся читаемый текст;
- `FB2` — заголовок и автор из описания книги, текст из всех `body`;
- `EPUB` — главы в порядке `spine`, заголовок и автор из OPF, картинки не распаковываются;
- `DOCX` — абзацы из `word/document.xml`, таблицы сохраняются, колонтитулы и сноски игнорируются;
- `.2books` — готовый параллельный перевод EN → RU с пословным выравниванием.

Для файла можно выбрать язык книги: автоопределение, английский или русский. Русская книга переводится на английский, английский текст становится основным, русский — параллельным. Если русская книга длиннее 200 000 символов, импорт отклоняется с сообщением о лимите: нужен готовый английский перевод или разбиение на части. Английские книги длиннее 200 000 символов по-прежнему импортируются без перевода.

Ограничения: обычный файл до 30 МБ, `.2books` до 4 МБ, извлечённый текст до 2 000 000 символов. PDF не поддерживается. Разбор и выравнивание выполняет Python-сервис; браузер отправляет файл напрямую в него.

Большие файлы и генерация в чате обрабатываются в фоне. После запуска можно уйти со страницы: прогресс отображается в правом нижнем углу, а готовая книга/текст появляется в подборке. Для фоновых уведомлений используется браузерный `Notification`, если пользователь разрешил его. Ещё не готовые тексты скрываются через `texts.ready`. Пока выполняется любая задача, новые загрузки и запросы в чате заблокированы.

Читалка получает окно из 4 страниц: 1 назад и 2 вперёд от текущей (у края — сдвигается), и кэширует их. Перелистывание по закэшированным страницам не ждёт сервер; следующие страницы догружаются заранее. В пагинаторе видно 5 страниц и поле для ввода номера.

### Книги `.2books`

Файл `.2books` — это ZIP с 19-байтным заголовком. Внутри `meta.json`, `toc.json` и `pages/N.json.gz`. Каждая страница содержит:

- `tokens1` — английские токены `[слово, префикс, суффикс, индекс русского токена, флаг]`;
- `tokens2` — русские токены `[слово, префикс, суффикс]`.

Импорт выполняет Python-сервис: он сохраняет оригинальное разбиение на страницы, английский и русский текст и пословное выравнивание. Индекс русского токена пересчитывается в существующее поле `en_tokens.align` через `ceil`, поэтому читалка подсвечивает нужное русское слово без изменения схемы. Русский текст хранится на каждой странице, без перераспределения.

В v1 не импортируются оглавление, сноски и аннотации. Автор книги не сохраняется: в таблице `texts` нет отдельной колонки. Читалка, как и раньше, показывает перевод при клике на слово; слова без словарной леммы остаются некликабельными.

## Структура

- `src/app` — страницы
- `src/actions` — серверные действия, по одному файлу
- `src/components` — компоненты
- `src/sorse` — вспомогательные функции
- `src/modules/database.ts` — схема таблиц и подключение
- `src/contexts` — клиентское состояние
- `src/middleware.tsx` — проверка cookie сессии
- `text-service` — Python/FastAPI: парсинг книг, страницы, лемматизация, выравнивание, LLM и задания

## Словарь

Слово лежит в `lemmas`: перевод, транскрипция, короткий пример, частота в `rank`, уровень CEFR в `level`. Варианты перевода — в `senses` (`pos`, `text`, `source`). Пример перевода — в `sense_examples` (`text_en`, `text_ru`) и ссылается на конкретное значение. Клик по форме слова ищет лемму в `word_forms`.

Звезда в читалке работает как переключатель: первое нажатие добавляет слово, повторное — убирает. При добавлении сохраняется предложение из текста вокруг выбранного слова в `user_words.context_en` (до 300 символов). Этот пример показывается на обратной стороне карточки тренировки в блоке «Из вашего текста» и на странице слова. Счётчик слов за день увеличивается только при добавлении.
