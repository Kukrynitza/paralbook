# Paralbook

Чтение английских текстов: подборка, библиотека, генерация в чате, карточка слова по второму клику, словарь и тренировка.

## Стек

Next.js 15, React 19, Kysely, PostgreSQL и отдельный Python-сервис обработки текста (FastAPI). База — Supabase через session pooler. Вход свой: пароль в `scrypt`, сессия в httpOnly-cookie. Supabase Auth не используется.

## Запуск

```bash
npm install
```

Скопируйте `.env.example` в `.env` и подставьте свои значения.

Сначала поднимите Python-сервис:

```bash
cd text-service
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python run.py
```

На Windows запускайте именно `run.py`: он включает `SelectorEventLoop`, нужный `psycopg`.

Затем Next.js:

```bash
npm run dev
```

Приложение откроется на http://localhost:5173, сервис — на http://127.0.0.1:8000.

Сборка: `npm run build`, затем `npm start`.

## Переменные

`DATABASE_CONNECTION_STRING` — строка session pooler (`*.pooler.supabase.com:5432`). Прямой хост `db.*.supabase.co` с Vercel не открывается.

`JWT_SECRET_KEY` — длинная случайная строка для подписи сессии Next.

`TEXT_SERVICE_URL` — внутренний адрес Python-сервиса.

`NEXT_PUBLIC_TEXT_SERVICE_URL` — адрес сервиса для прямых загрузок из браузера.

`TEXT_SERVICE_TOKEN` — общий секрет для вызовов Next → сервис.

`TEXT_SERVICE_JWT_SECRET` — секрет для короткоживущих токенов пользователя (загрузка файлов и настройки LLM).

`LLM_SETTINGS_SECRET`, `LLM_LEGACY_SECRET`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_CHAT_MODEL` читает Python-сервис. `LLM_SETTINGS_SECRET` есть только у сервиса; `LLM_LEGACY_SECRET` нужен один раз для перешифровки старых ключей `v1`.

Секреты остаются только на сервере. В клиентский бандл попадает только публичный адрес `NEXT_PUBLIC_TEXT_SERVICE_URL`.

## Нейросеть и text-service

Генерация текста, перевод загруженных книг и работа с LLM-ключами вынесены в Python-сервис.

Пользователь указывает OpenAI-совместимый Base URL, модель и API-ключ. Ключ шифруется AES-256-GCM в `llm_settings`; секрет `LLM_SETTINGS_SECRET` известен только сервису. Ввод и проверка ключа идут напрямую в Python по короткоживущему токену от Next, поэтому Next не хранит и не расшифровывает ключ.

Таблица `llm_settings` должна существовать (тип `user_id` совпадает с `profiles.id`; ниже предполагается `uuid`):

```sql
create table if not exists llm_settings (
  user_id uuid primary key references profiles(id) on delete cascade,
  base_url text not null,
  model text not null,
  api_key_ciphertext text,
  updated_at timestamptz not null default now()
);
```

Сервис сам создаёт `text_jobs` для асинхронных заданий генерации и импорта. Для скрытия ещё не обработанных текстов нужна колонка:

```sql
alter table texts add column if not exists ready boolean not null default true;
```

Старые ключи формата `v1`, зашифрованные Next, автоматически перешифровываются при чтении, если задан `LLM_LEGACY_SECRET`.

Если у пользователя нет личного ключа, используется `LLM_API_KEY` из окружения сервиса. Для локальных моделей (Ollama, LM Studio) ключ не обязателен.

Озвучка слов идёт через `edge-tts` в Python-сервисе. Голос задаётся `TTS_VOICE` (по умолчанию `en-US-AriaNeural`); аудио кэшируется, а при недоступности сервиса клиент откатывается на браузерный `speechSynthesis`.

## Тема, цвета и шрифты

Тема хранится в аккаунте в `user_themes.prefs` (jsonb), в браузере остаётся кэш для отрисовки до загрузки из БД. Таблица:

```sql
create table if not exists user_themes (
  user_id uuid primary key references profiles(id) on delete cascade,
  prefs jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);
```

- У каждого раздела свой акцент: подборка, библиотека, чат, читалка, добавление, словарь и тренировка, статистика, друзья, настройки. Цвета меняются в «Настройки → Внешний вид → Настроить цвета»; связанные разделы делят один цвет.
- Режимы: системная, светлая, тёмная и своя. В своей теме задаются три цвета — фон, карточки и текст; границы, приглушённый текст, фон вне телефона и мягкие подложки выводятся автоматически, контраст текста проверяется.
- Шрифты: отдельно для интерфейса и для чтения, размер текста S/M/L. Каталог (включая барочные, плакатные и рукописные семейства) собирается через `next/font` и раздаётся с нашего домена; в БД хранятся только ключи, внешних запросов к Google Fonts в рантайме нет.
- `profiles.theme` остаётся только как начальный режим для пользователей без строки в `user_themes`.

## Добавление текста и загрузка файлов

**Страница «Добавить»** (`/text`, кнопка «Добавить текст» в чате). Сверху — загрузка файла, ниже — ручной ввод.

Файл книги поддерживает:

- `TXT` — с определением кодировки: BOM и UTF-16, UTF-8, windows-1251, KOI8-R и другие однобайтовые кодировки через `charset_normalizer` и частотную проверку русских букв;
- `Markdown` — разметка убирается, остаётся читаемый текст;
- `FB2` — заголовок и автор из описания книги, текст из всех `body`;
- `EPUB` — главы в порядке `spine`, заголовок и автор из OPF, картинки не распаковываются;
- `DOCX` — абзацы из `word/document.xml`, таблицы сохраняются, колонтитулы и сноски игнорируются;
- `.2books` — готовый параллельный перевод EN → RU с пословным выравниванием.

Для файла можно выбрать язык книги: автоопределение, английский или русский. Русская книга переводится на английский, английский текст становится основным, русский — параллельным. Если русская книга длиннее 200 000 символов, импорт отклоняется с сообщением о лимите: нужен готовый английский перевод или разбиение на части. Английская книга длиннее 200 000 символов тоже отклоняется: без перевода текст не сохраняется, нужен `.2books` с готовым переводом или разбиение на части.

Кнопка «Добавить текст вручную» раскрывает два поля — английский и русский текст:

- заполнено только одно поле — сервис переводит его на второй язык (EN → RU или RU → EN);
- заполнены оба — перевода нет, сервис только выравнивает готовые тексты по абзацам и предложениям;
- лимит — 200 000 символов на каждое поле; при превышении задача не создаётся;
- название для ручного ввода обязательно; для файла, если оно не задано, берётся из метаданных или первого предложения текста;
- абзацы лучше разделять пустой строкой: при одинаковом количестве абзацев соответствие точнее.

Без настроенного ключа нейросети добавление текстов заблокировано: доступны только `.2books` с готовым переводом и ручной ввод, где заполнены оба поля. Страницы «Добавить» и «Чат» показывают предупреждение, а попытка отправить текст без перевода выводит боковой баннер со ссылкой на настройки. Такие же баннеры появляются при ошибках задач, сервиса и сохранения настроек.

Справка в настройках (иконка `?` в шапке) состоит из двух вкладок: «Инструкция» — что это, с чего начать, где что находится, как читать, слова и тренировка, добавление текстов, нейросеть, ограничения и частые проблемы; «О системе» — версии, состояние сервиса, модель и счётчики с кнопкой «Скопировать сведения».

Ограничения: обычный файл до 30 МБ, `.2books` до 4 МБ, извлечённый текст до 2 000 000 символов. PDF не поддерживается. Разбор и выравнивание выполняет Python-сервис; браузер отправляет файл напрямую в него.

Большие файлы и генерация в чате обрабатываются в фоне. После запуска можно уйти со страницы: прогресс отображается в правом нижнем углу, а готовая книга/текст появляется в подборке. Для фоновых уведомлений используется браузерный `Notification`, если пользователь разрешил его. Ещё не готовые тексты скрываются через `texts.ready`. Пока выполняется любая задача, новые загрузки и запросы в чате заблокированы.

У пользователя может быть только одна активная задача. Задача создаётся сразу при старте импорта, ещё до отправки файла, поэтому вторую загрузку нельзя начать даже из другой вкладки. Активную задачу можно остановить из нижнего дока: сначала показывается подтверждение, затем отменяется HTTP-загрузка и фоновая задача, а текст удаляется. Импорт работает по принципу «всё или ничего»: при ошибке текст, страницы и запись в подборке удаляются, а в доке остаётся карточка ошибки с кнопкой «Повторить». Брошенные задачи и скрытые тексты убирает фоновый уборщик.

Размер блока перевода настраивается в настройках: по предложениям или по приблизительным токенам. Меньше — точнее, но больше запросов; больше — быстрее и дешевле. Настройка хранится в браузере и передаётся вместе с импортом. Новые тексты считают время чтения по 75 словам в минуту.

Читалка получает окно из 4 страниц: 1 назад и 2 вперёд от текущей (у края — сдвигается), и кэширует их. Перелистывание по закэшированным страницам не ждёт сервер; следующие страницы догружаются заранее. В пагинаторе видно 5 страниц и поле для ввода номера. На последней странице вместо стрелки показывается кнопка «Завершить».

Для обычных текстов каждому английскому слову сопоставляется русский перевод из словаря: среди всех вхождений перевода на странице выбирается ближайшее к ожидаемой позиции, результат хранится в `en_tokens.ru_align` (индекс русского слова в пределах страницы). Поэтому подсветка ставится ровно на найденное слово, без обратного пересчёта. Если перевода на странице нет, подсвечивается ближайшее по позиции русское слово — так видно, где примерно находится нажатое слово. Для служебных слов (`is`, `a`, `the` и т. п.) позиция выбирается всегда, даже если в словаре есть далёкое совпадение: так подсветка не улетает в другой конец страницы. Без `ru_align` остаются только пробелы и пунктуация, по которым нет клика. Старое поле `align` сохранено для `.2books` и страниц, размеченных до этого изменения.

### Книги `.2books`

Файл `.2books` — это ZIP с 19-байтным заголовком. Внутри `meta.json`, `toc.json` и `pages/N.json.gz`. Каждая страница содержит:

- `tokens1` — английские токены `[слово, префикс, суффикс, индекс русского токена, флаг]`;
- `tokens2` — русские токены `[слово, префикс, суффикс]`.

Импорт выполняет Python-сервис: он сохраняет оригинальное разбиение на страницы, английский и русский текст и пословное выравнивание. Индекс русского токена пересчитывается в существующее поле `en_tokens.align` через `ceil` — для `.2books` читалка использует старую схему. Русский текст хранится на каждой странице, без перераспределения.

В v1 не импортируются оглавление, сноски и аннотации. Автор книги не сохраняется: в таблице `texts` нет отдельной колонки. Читалка, как и раньше, показывает перевод при клике на слово; слова без словарной леммы остаются некликабельными.

## Структура

- `src/app` — страницы
- `src/actions` — серверные действия, по одному файлу
- `src/components` — компоненты
- `src/sorse` — вспомогательные функции
- `src/modules/database.ts` — схема таблиц и подключение
- `src/contexts` — клиентское состояние
- `src/middleware.tsx` — проверка cookie сессии
- `text-service` — Python/FastAPI: парсинг книг, страницы, лемматизация, выравнивание, LLM и задания

## Словарь

Слово лежит в `lemmas`: перевод, транскрипция, короткий пример, частота в `rank`, уровень CEFR в `level`. Варианты перевода — в `senses` (`pos`, `text`, `source`). Пример перевода — в `sense_examples` (`text_en`, `text_ru`) и ссылается на конкретное значение. Клик по форме слова ищет лемму в `word_forms`.

Звезда в читалке работает как переключатель: первое нажатие добавляет слово, повторное — убирает. При добавлении сохраняется предложение из текста вокруг выбранного слова в `user_words.context_en` (до 300 символов). Этот пример показывается на обратной стороне карточки тренировки в блоке «Из вашего текста» и на странице слова.

Добавленное слово попадает в «Свои слова» и в колоду новых. Дневной лимит новых слов и дополнительное количество на сегодня хранятся в `localStorage`; при превышении лимита читалка и тренировка предлагают подтвердить дополнительные слова. Слово расходует дневной план, когда пользователь впервые его прошёл: «Знаю» сразу засчитывает его, «Не знаю» отправляет в повтор до первого «Знаю». Сначала набирается план новых слов, затем каждое слово повторяется до нажатия «Знаю»; в «Новых» счётчик справа показывает пройденные новые слова, например 3/10. В «Смешанном» новые и повторения идут вперемешку, а счётчик показывает пройденные слова: сделано / всего. Слова, прошедшие «Не знаю → Знаю», уходят в повторение. Интервалы как в ReWord: 30 минут, 2 часа, 1 день, 7 дней и финальная проверка через 60 дней; после неё слово считается выученным. Ошибка на повторении уменьшает интервал на шаг, но не сбрасывает счётчик правильных ответов. Если в пачке закончились кандидаты, а план ещё не заполнен, сервис автоматически добирает следующую пачку. Когда новые заканчиваются, экран предлагает «Добавить ещё новых» или перейти к повторению; при исчерпании повторений показывается время следующего подхода.

## Тесты

- `npm test` — Vitest: чистые функции фронтенда (`sentenceAt`, `translationPrefs`, `splitByShare`, `preview`, `shortHint`, `dayWord`, `shuffle`, `niceMax`, дневной лимит).
- `npm run test:e2e` — Playwright: импорт файла и текста, отмена, ошибки, читалка, словарь, тренировка, чат, библиотека, публикация, настройки.
- `cd text-service && .venv\Scripts\python.exe -m pytest tests -q` — кодировки, нарезка перевода, пагинация и выравнивание.

Для e2e нужны `JWT_SECRET_KEY`, `DATABASE_CONNECTION_STRING` и `E2E_USER_ID` — id существующего тестового пользователя. В аккаунте должны быть тексты `Marshall 4`, `My Best Friend` и `Mario and Pizza`: на них проверяются читалка, публикация и бейдж. Playwright сам поднимает Next и Python-сервис, если они не запущены. После прогона `e2e/global-teardown.ts` удаляет тестовые тексты, сбрасывает публикацию и прогресс, чтобы не засорять аккаунт.
